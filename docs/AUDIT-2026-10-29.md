# Anchor performance and interface audit — October 29, 2026

This audit prioritizes unnecessary background work, retained image memory, duplicated controls, and coherent navigation. It includes a repository-wide source/dependency inventory and targeted deeper review of startup, service ownership, timers, observers, image caches, media, camera, dashboard, and settings. It does not claim that every line or every hardware-dependent workflow has been manually exercised.

## Scope and decisions

The current app has 436 native Swift files (about 120,000 lines) and 674 utility Swift files (about 292,000 lines), excluding dependencies, builds, and tests. Existing feature gates, lazy utility services, shared system sampling, and native ownership rules were reviewed before adding new machinery. The reachability audit still finds consumers and settings for every feature it checks.

Production Swift code has a net reduction of 370 lines in the implementation commits; focused tests and audit tooling were added separately. The main removals are duplicated lock-screen configuration panels, three separate recorder cache implementations, overlapping native icon memory caches, a permanent calendar refresh loop, a permanent RSS restart-warning poller, unused settings helpers, an unused timer wrapper, and unused direct package dependencies. Unique features and saved user data are retained.

## Implemented performance changes

| Area | Finding | Result |
| --- | --- | --- |
| Launcher icons | Warm-up and visible requests could decode/write the same icon concurrently; separate memory caches retained overlapping images. | One purgeable cache with a 24 MiB cost limit and 256-entry limit; shared in-flight requests; at most two decode workers. Cache clearing invalidates old completions. Revision validation uses fresh file metadata. |
| App switcher | Startup cached icons for background agents that can never appear in the ring. | Only regular applications other than Anchor enter its retained icon map. |
| Recorder | Three independently implemented caches had inconsistent eviction. The image cache could exceed roughly 96 MB, and count-based text caching did not bound bitmap bytes. | One shared cache implementation; image/text/cursor budgets of 32/16/4 MiB, checked before insertion using row stride. Oversize images remain usable by the caller without global retention. Memory-pressure events and editor teardown clear reusable images. Active render plans remain valid. |
| Clipboard | Tiny file/source-app markers retained multi-resolution Finder icons. | Rasterize markers at their displayed 20-point size; file-icon cache gains a 2 MiB advisory cost limit; source-app retention is count bounded. |
| Dashboard | A closed window retained the whole view tree. Minimized system cards could keep leases. | Close/lock/window-arrangement dismissal releases dashboard content; minimizing/occlusion parks sampling and date/calendar updates while retaining drafts. The selected tab survives reopening. |
| Calendar | A singleton ran a permanent minute loop for one lock-screen consumer. Cancelled debounce tasks still refreshed. | Use the lock-screen widget's existing visible ticker. Cancelled deferred refreshes exit before fetching. Dashboard upcoming events reuse the existing seven-day event cache, with visible-only refresh and debounced EventKit invalidation. |
| Camera mirror | A delayed permission response could build a session after the preview disappeared. Concurrent start/stop tasks could finish out of order. | Track current presentation demand and request generation; reject stale responses/completions; serialize session start and stop. Device changes also respect a pending start. |
| YouTube Music | Recursive reconnects retained old controllers; termination cancelled the observer needed for a subsequent launch; unchanged metadata repeatedly fetched artwork. | One cancellable retry task, teardown of timers/tasks/socket, retained launch observation, URL-keyed artwork requests, stale-artwork guards, and fallback timer tolerance. |
| Spectrum | Playing could acquire audio before attachment; hidden/occluded windows continued 30 Hz work. Every bar committed its own transaction, with recurring diagnostic output. | Acquire only for a visible playing view; release on hiding, minimization, occlusion, or detachment. One transaction per frame; remove recurring console output; bound layer count against corrupt preferences. |
| Memory warning monitor | Polled RSS forever and opened a modal restart prompt above a fixed 1 GiB threshold, regardless of legitimate media work or system pressure. | Remove the poller and arbitrary restart interruption. Purgeable/pressure-aware caches handle reclaimable memory; diagnostic measurement is explicit. |
| Dependencies | Pow and the Open-Meteo package had no linked product or imports. Collections was linked without usage. | Remove all three direct dependencies and their unused product/reference entries. Weather's existing URLSession-based Open-Meteo implementation remains. |

Cache limits describe reusable cache retention, not total app memory. Visible images, render plans, framework allocations, audio buffers, and optional speech/media work can hold additional memory. NSCache cost limits are advisory; the recorder's explicit byte accounting is strict.

## Settings and dashboard

Settings now has stable task-based groups: general controls, Workspace, Notch & Lock Screen, Sound & Display, Productivity, System, Connections & AI, and Developer. Selecting a pane no longer expands a long list inside the sidebar and moves every item below it. A Sections menu in the pane header provides direct navigation.

Lock Screen owns its material, media, timer, calendar, and reminder options. Appearance, Media, Timer, and Calendar link directly to the relevant section. Removing these mirrored controls does not reset Defaults keys. Album-art parallax moved to the same canonical page. Search results point to the canonical pane; legacy entries without a real scroll anchor open the relevant pane without issuing a dead scroll request.

The index reader now understands multiple settings views in one Swift file, so Bluetooth options route to Bluetooth Devices instead of Volume & Brightness. It also indexes both supported Section declaration styles. There are 343 highlighted rows, 360 search entries, and 126 indexed sections. Search supports native field-editor keyboard suggestion navigation, clear search, and an explicit no-results state. The window restores its last pane and reports that pane in its native title. Snapshot navigation does not persist a last-pane change or read the notification-topic credential. Settings scroll transitions respect Reduce Motion. Opening calendar settings reads permission state; access is requested through its explicit connection action. Automation usage text names Notes alongside media, Finder, and Terminal.

Dashboard uses consistent card surfaces, spacing, hierarchy, date context, and distinct Tools/Customize controls. Its default overview includes tasks, upcoming events, playback, focus, favorite tools, and quick controls. System health reuses the existing Stats view and sampler for CPU, GPU, memory pressure, temperatures, battery, and network rates. Users can hide or add cards; intentionally customized layouts remain intact. No new independent hardware sampler was added. Empty playback now displays an honest idle state instead of developer placeholder song metadata. Icon-only dashboard controls have explicit accessibility labels. Notch width sliders now have separate label/value rows, usable full-width tracks, and point units. Media explanations are shorter and user-focused; remaining user-facing Atoll labels in the touched settings were corrected without changing attribution.

## Research applied

- [Apple HIG: Settings](https://developer.apple.com/design/human-interface-guidelines/settings): minimize unnecessary settings, group related options, provide task-specific choices in context, maintain stable navigation, restore the last pane, and reflect the pane in the window title.
- [Apple HIG: Layout](https://developer.apple.com/design/human-interface-guidelines/layout): express hierarchy with order/alignment/spacing; group related controls; test narrow and wide layouts.
- [Apple: Demystify SwiftUI performance](https://developer.apple.com/videos/play/wwdc2023/10160/): scope changing dependencies to the views that need them, keep expensive work outside body, and use stable identity. Hardware observations remain at dashboard leaves.
- [Apple: Energy efficiency and timers](https://developer.apple.com/library/archive/documentation/Performance/Conceptual/EnergyGuide-iOS/MinimizeTimerUse.html): invalidate unnecessary timers, use suitable intervals and tolerances, and prefer events when available. The general principle applies here; platform-specific APIs differ.
- [Apple: Reducing memory use](https://developer.apple.com/documentation/xcode/reducing-your-app-s-memory-use): measure memory under actual workflows and reduce avoidable retention. Bitmap budgets use decoded bytes rather than compressed file sizes.
- [Apple: Improving app performance](https://developer.apple.com/documentation/xcode/improving-your-app-s-performance): profile, prioritize, change, and measure again. RSS and physical footprint are reported separately; old benchmark rows are not reused as current results.

## Measurement boundaries

An initial 90-second sample of the old installed process reported mean CPU 1.31%, median 0.48%, p90 3.36%, and mean RSS 62.8 MB. It began before the recommended five-minute settle time and included launch activity, so it is not a controlled comparison baseline. A later five-second sample of that same older process, after roughly four hours of use, reported 220.4M physical footprint and a 347.7M peak; its main thread was almost entirely waiting. Physical footprint includes memory that RSS alone does not describe.

The cache bounds and stopped work are tested behavioral improvements. A percentage claim about overall CPU/RAM savings would require equivalent cold starts, identical settings/workflows, equal uptime, and repeated recordings. This audit does not infer such a percentage from unlike process histories.

## Remaining consolidation and deeper work

The [earlier duplicate-feature inventory](DUPLICATE-FEATURE-AUDIT-2026-10-28.md) still applies to separate persisted clipboard/shelf stores, audio processing engines, camera presentations, and alternative utility input/window engines. Their overlap is real, but their saved contents and capabilities differ. Ownership prevents competing active replacements in supported paths; it does not make their data stores identical. They were not deleted as if they were disposable dead code.

The next consolidation should migrate clipboard/shelf contents through versioned, reversible, idempotent adapters, preserving rich text, image/file references, pins, inaccessible bookmarks, and privacy/retention rules. Audio engine consolidation also needs route changes, multi-process apps, EQ, boost, and uninterrupted playback tests. Shared camera ownership needs overlapping-preview and device-switch tests. These are larger follow-on implementations, not completed claims in this audit.

Further performance work should be guided by evidence:

1. Capture Instruments Allocations/VM Tracker generations before and after repeated settings, launcher, clipboard, player, and recorder cycles. Prioritize allocations still live after their surfaces close. Measure physical footprint and compressed memory as well as RSS.
2. Use Time Profiler and the SwiftUI instrument on search, resize, per-app audio, and large clipboard/shelf collections. Migrate high-churn ObservableObject graphs to finer observation only where update traces justify it.
3. Diagnose wakeups with System Trace/Energy tools under disabled, normal, and heavily enabled feature profiles. Pasteboard and API-only integrations still need polling; avoid claiming universal zero polling. Keep required background alerts distinct from visible-only sampling.
4. Audit Swift concurrency warnings incrementally. The target currently compiles in Swift 5 mode; a wholesale Swift 6 migration is not part of this change. Audio callback isolation and bounded, allocation-free real-time paths need particular care.
5. Use display-synchronized/adaptive rendering for active visualizers if traces show a benefit. A simple visible-only 30 Hz visualizer is currently preferable to introducing more scheduling machinery without measured need.
6. Consider helper-process isolation for optional transcription or heavy exports only if memory-lifetime evidence supports the IPC, signing, startup, and recovery cost. Do not unload user work or interrupt an active export merely to lower a dashboard number.

Hardware checks still needed: physical camera LED/permission timing and device changes, audio continuity/device switching, external-display reconnect and sleep/wake, held shortcuts/gestures, and prolonged optional-service use. Mocks and rendered snapshots do not prove these paths.
